# 千绘 · 角色随机师 V2 — 分类筛选 + 手动指定角色 设计文档

日期: 2026-08-28
目标节点: `QianhuiRandomCharacter`（千绘 · 角色随机师 V1，nodes/role_name_node.py）
状态: 已确认设计，待实施

## 背景与问题

现有节点（V1）只有两个下拉：作品类型（🎲随机/🎮游戏/📺动漫）、模型类型，纯随机输出角色名。
用户反馈两个问题：

1. **随机混乱**——随机池不分性别/兽类/机械，抽到男角色、兽角色难以控制。
2. **无法手动指定**——想指定"原神的胡桃"这类具体角色做不到。

## 目标

1. 随机抽取时可按分类过滤：性别（女/男）、兽类·福瑞、机械·人造人，且可组合（女+兽=兽娘）。
2. 支持手动指定：先选作品（如"原神"），角色下拉联动只剩该作品角色，可从中选具体角色，也可"作品内随机"。
3. 保持 V1 的输出格式（英文提示词名 + 中文显示名）与转义规则不变。

非目标：不改其他节点、不做性别概率权重、不做多选、不加前端主题/样式改动。

## 数据层

### 新增 `data/role_category.json`
角色分类标签，**多标签**单个值：`{"role": ["female"], "frieren": ["female"], "some_beast": ["male", "beast"]}`

标签集合（4 个）：
- `female` — 女性角色（含女装/扶他少量边缘归 female 或男，按常识）
- `male` — 男性角色（伪娘如"男性 (1boy, girly)"类归 male）
- `beast` — 兽类外形：兽娘、兽人/福瑞、龙娘、狐/猫/犬/狼/兔/牛/羊/鼠娘、恶魔/恶魔角系不变异者不算（恶魔单独标 female/male 即可）
- `robot` — 机械娘、人造人、赛博格、Android 系

规则：
- 角色必标 0~2 个标签；female/male 一般二选一（非人类无性别如特殊生物可不标性别，仅标 beast/robot 或留空）
- **留空 = 未知/无法判定**：随机「不限」时仍会被抽中；固定分类筛选时排除
- 生成方式：由 AI（Claude 会话）基于英文角色名 + 中文名映射知识全量标注 1629 个角色，知名角色准确率高；冷门不确定的留空保底

### 新增 `data/work_cn.json`
版权 tag → 作品中文名映射：`{"genshin_impact": "原神", "honkai:_star_rail": "崩坏：星穹铁道", ...}`

- 覆盖全部实际出现的版权 tag（约 300 个）；未收录者 display 回退英文 tag
- 生成方式：AI 全量生成，Danbooru tag 惯例与常见译名

### 现有数据不变
`role_owner.json`（角色→版权）、`role_names.json`（角色+热度）、`role_names_cn.json`（中文名）不动。

## 节点界面

INPUT_TYPES 5 个下拉（减掉旧"作品类型"外的新增参数；模型类型不用 emoji，风格保持简洁；仅作品类型沿用现有单 emoji 风格）：

| 参数 | 类型 | 可选值 |
|---|---|---|
| 作品类型 | COMBO | `["🎲随机类型", "🎮只出游戏", "📺只出动漫", "🎯指定作品"]` |
| 抽取分类 | COMBO | `["不限", "女", "男", "兽类·福瑞", "机械·人造人", "兽娘", "机械娘"]` |
| 模型类型 | COMBO | `["SDXL", "anima (括号转义)"]`（原样） |
| 指定作品 | COMBO | `["（未指定）"]` + 全部作品，display `中文名 (tag)`，无中文名则 tag 本身 |
| 指定角色 | COMBO | `["（未指定）"]` + 全部角色，display `中文名 (英文名)`，无中文名则英文名 |

说明：
- 指定作品/指定角色下拉常驻（ComfyUI 无条件渲染），仅「🎯指定作品」模式读取其值
- display 拆分规则：取字符串最后一个 `" ("` 拆分得到 tag/英文名；**未指定**为固定哨兵值
- 抽取分类内部映射：
  - 不限 → 不过滤
  - 女 → 必须 female；男 → 必须 male
  - 兽类·福瑞 → 必须 beast（不筛性别）；机械·人造人 → 必须 robot
  - 兽娘 → female 且 beast；机械娘 → female 且 robot

## JS 联动菜单

新增前端扩展实现"选作品 → 角色下拉即时过滤"：

- `__init__.py` 增加 `WEB_DIRECTORY = "./js"`
- 新增 `js/role_random.js`：`app.registerExtension`，在 `beforeRegisterNodeDef` 中：
  1. 节点创建时 fetch 后端提供的角色数据 JSON（一次性，含作品列表、作品→角色映射、中文名）
  2. 监听「指定作品」widget 的 `callback`（值变化）：把「指定角色」widget 的 `options.values` 替换为该作品的角色列表（保留首项"（未指定）"），并将 value 重置为"（未指定）"；作品切回"（未指定）"时恢复全量列表
  3. 数据来源：`fetch("/qianhui_role_data")` 一次性获取全文数据（约 150KB，节点创建时取一次并缓存）
- 后端路由 `GET /qianhui_role_data` 在 `__init__.py` 中注册（`try/except` 保护，注册失败不影响其余节点），payload 构建函数 `build_payload()` 放在 `role_name_node.py`（纯标准库，可独立测试）；payload 结构：作品列表（tag+中文名）、每个作品的角色列表（danbooru 名+中文名）
- 序列化/还原：用户工作流还原时角色值若不在当前作品列表内（换过作品），按 ComfyUI 默认行为保留原值；后端解析时以角色名精确匹配——若该角色名不在作品列表内则按"作品内随机"处理，避免输出错角色（见错误处理）

### JS 失败回退
JS 不加载（旧版 ComfyUI / JS 报错）时：指定作品、指定角色下拉仍为静态全量列表，后端逻辑全部可用（只是没有联动）。

## 抽取逻辑

设 mode = 作品类型，cat = 抽取分类映射的标签条件，work = 指定作品值，role = 指定角色值：

1. `mode == "🎯指定作品"`：
   a. role 为具体角色 → **直接输出该角色**（跳过分类筛选；作品仅作导航用途；角色必须属于所选作品，见错误处理）
   b. role 为"（未指定）"且 work 为具体作品 → 该作品角色池内按 cat 过滤随机；过滤后为空返回 `("(该作品下无匹配角色)",)`
   c. 两者均为"（未指定）" → 回退到 mode="🎲随机类型" 的抽取逻辑（含 cat 过滤）
2. `mode != "🎯指定作品"` → 忽略 work/role 值，按现有类型加权随机（互斥类型如"女"只在 female 池内），再按 cat 过滤：
   - 抽取顺序：先按类型（随机/游戏/动漫）按现有权重，再按 cat 过滤；过滤后池空则返回 `("(无匹配角色)",)`

优先级注意：**回退规则不触发误输出**——只在 mode=指定作品时读 work/role；其他模式下下拉残留值一律忽略。

## 输出

- `RETURN_TYPES = ("STRING", "STRING")`、`RETURN_NAMES = ("角色名(英文)", "角色名(中文)")`、`FUNCTION = "generate_role_name"`、`CATEGORY = "千绘/角色"` 全部不变
- 英文输出沿用 `escape_name`（SDXL 括号 / anima 反斜杠转义），角色无括号时追加版权 tag 消歧义——不变
- 中文显示：`中文名(版权tag)`，无中文名回退英文名——不变
- `IS_CHANGED` 保持 `time.time()`（每次都随机）

## 错误处理

- data 文件缺失（role_category/work_cn）→ 现有 `(无角色数据)` 或回退：分类文件缺失时视为全量"不限"；作品中文名缺失显示英文 tag
- 作品内角色列表为空 / 分类过滤后为空 → `("(无匹配角色)",)`（中文列同值）
- 角色指定但不在所选作品内（JS 未联动或还原旧值）→ 按"作品内随机"处理，绝不输出错作品角色
